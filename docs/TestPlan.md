# План тестирования MaxFunkTetris2024

Этот документ описывает набор юнит-, интеграционных, рендеринговых и окруженческих сценариев для консольной игры MaxFunkTetris2024.  
Его цель — зафиксировать, **что именно** должно быть проверено, чтобы:

- логика фигур и поля работала корректно;
- стейт-машина состояний (меню / игра / пауза / help / settings / game over) вела себя предсказуемо;
- консольный интерфейс был стабильным и без артефактов;
- игра корректно работала в разных средах и сборках.

Сценарии можно реализовывать как автоматические тесты (xUnit/NUnit) и/или использовать как чек-лист для ручного прогона.

---

## 1. Типы тестов и окружения

**Уровни тестирования**

- Юнит-тесты ядра: `Tetromino`, `GameBoard`, чистая логика `Game` без привязки к консоли.
- Интеграционные тесты: связка `Game` + `GameBoard` + падение фигур, очистка линий, стейт-машина.
- Тесты рендеринга: корректность работы `GameRenderer`, `UiFrameRenderer`, `UiStatsRenderer`, экранов меню/help/settings/паузного оверлея.
- Окруженческие проверки: разные ОС, терминалы, кодировки, размеры окна.
- Дымовой (smoke) чек-лист перед релизом.

**Окружения**

- .NET 8 (целевой фреймворк), опционально прогон под .NET 7.
- ОС: Windows, Linux, macOS (консоль).
- Терминалы: Windows Terminal / PowerShell / стандартные терминалы bash/zsh.

## 2. Юнит-тесты ядра логики

### 2.1. Tetromino

1. **Поворот всех 7 фигур**

   - Для каждой формы (O, I, T, J, L, S, Z):
     - Один поворот `Rotate()`:
       - размеры массива меняются ожидаемо: `rows' = cols`, `cols' = rows`;
       - количество единиц (`1`) сохраняется;
       - индексы не выходят за границы.
     - Четыре последовательных поворота возвращают форму к исходному состоянию (матрица идентична).

2. **Проверка стартовой позиции**

   - Конструктор `Tetromino(int shapeIndex)`:
     - `Y == 0`;
     - `X == 5 - Shape.GetLength(1) / 2` для фигур разной ширины;
     - ни одна единица стартовой фигуры не выходит за правую границу поля шириной 10–15 клеток (по договорённости).

3. **SaveState / RestoreState**

   - Вызвать `SaveState()`, затем изменить `Shape`, `X`, `Y` произвольным образом.
   - Вызвать `RestoreState(...)` с сохранённым снимком.
   - Убедиться, что:
     - `Shape` поэлементно совпадает с сохранённой копией;
     - `X` и `Y` восстановились;
     - никаких дополнительных ссылок на старый массив нет (Clone).

4. **Rotate с откатом при коллизии (поведение `Game.RotateTetromino`)**

   - Смоделировать ситуацию столкновения (например, фигура вплотную к стене).
   - Вызвать `RotateTetromino()`:
     - при наличии коллизии `Shape`, `X`, `Y` должны остаться без изменений (состояние откатывается через SaveState/RestoreState).

### 2.2. GameBoard

1. **GameBoard.IsCollision — границы**

   Для каждой фигуры (можно взять несколько простых):

   - `x = -1` → `IsCollision` возвращает `true`.
   - `x = Width` (фигура полностью за правой границей) → `true`.
   - `y = Height` (фигура «сидит» на дне) → `true`.
   - `y < 0` (часть фигуры над верхом поля) при отсутствии других блоков:
     - коллизии **нет**, пока фигура не врезалась в существующие блоки (используемая логика).

2. **GameBoard.IsCollision — столкновение с занятыми клетками**

   - В сетке `Grid` пометить одну или несколько клеток как занятые.
   - Расположить фигуру так, чтобы один из её блоков накладывался на занятую клетку.
   - `IsCollision` должен вернуть `true`.

3. **MergeTetromino — запись только в пределах поля**

   - Разместить фигуру так, чтобы часть её блоков была над верхом (`Y < 0`) или за пределами по X.
   - Вызвать `MergeTetromino`.
   - Убедиться, что:
     - в `Grid` заполняются только клетки с координатами в диапазоне `[0..Width-1] × [0..Height-1]`;
     - не происходит исключений по выходу за границы массива;
     - для блоков с отрицательным `y` запись не выполняется.

4. **ClearLines и ShiftLinesDown — одиночная строка**

   - Заполнить одну строку полностью, остальные оставить частично заполненными или пустыми.
   - Вызвать `ClearLines`:
     - вернуть должно `1`;
     - все строки выше сдвигаются вниз на одну позицию;
     - верхняя строка становится полностью пустой (все нули).

5. **ClearLines и ShiftLinesDown — несколько строк подряд**

   - Заполнить две соседние строки целиком (например, `y = 18` и `y = 19`).
   - Вызвать `ClearLines`:
     - вернуть должно `2`;
     - обеспечить, что цикл по `y` правильно повторно проверяет сдвинутую строку (нет пропущенной линии);
     - верхние строки корректно сдвинуты, две верхние строки — нулевые.

6. **ClearLines — строки через одну**

   - Заполнить, например, строки `y = 17` и `y = 19`, оставить `y = 18` частично заполненной.
   - Убедиться, что за один проход очищаются только полностью заполненные строки, остальные корректно «проседают» вниз.

### 2.3. Game (логика без консоли)

Для этих тестов допускается:

- использовать `InternalsVisibleTo` или
- добавить тестовый конструктор/методы (или reflection), чтобы получить доступ к приватным полям (`_tick`, `_dropInterval`, `_state`, `_score`, `_linesCleared`, `_difficulty`).

1. **GetDropInterval / сложность**

   - Для `Difficulty.Easy`, `Normal`, `Hard` `GetDropInterval` возвращает соответственно `10`, `6`, `3`.
   - При неизвестном значении (если будет добавлено) возвращается базовый интервал (например, `6`).

2. **ResetGame сбрасывает состояние**

   - После серии ходов и набора очков вызвать `ResetGame`:
     - `_score == 0`;
     - `_linesCleared == 0`;
     - `_tick == 0`;
     - `currentTetromino` не null и коллизий на старте нет;
     - `board.Grid` полностью нулевая.

3. **MoveTetromino / MoveTetrominoDown**

   - При отсутствии коллизий координаты фигуры меняются ровно на (dx, dy).
   - При столкновении координаты остаются прежними, метод возвращает `false`.

4. **Обновление падения по кадрам**

   - Задать `_dropInterval = 3`.
   - Вызвать `UpdatePlaying` несколько раз, контролируя `_tick`:
     - фигура перемещается вниз только когда `_tick % _dropInterval == 0`;
     - на других кадрах позиция по `Y` не меняется.
   - При ручном сдвиге вниз (симуляция `DownArrow`) проверить, что изменение `_tick` не ломает периодичность автоматического падения.

5. **Начисление очков и линий**

   - Сформировать ситуацию, где `ClearLines` возвращает 1, 2, 4:
     - `_score` увеличивается на `clearedLines * 100`;
     - `_linesCleared` накапливает общее количество убранных линий.

6. **Уровень сложности отображения (CurrentLevel)**

   - При `_linesCleared = 0…9` `CurrentLevel == 1`.
   - При `_linesCleared = 10…19` `CurrentLevel == 2`, и т.д.
   - Проверить, что `CurrentLevel >= 1` всегда.
   - Убедиться, что смена уровня **не** меняет `_dropInterval` (он зависит только от `_difficulty`).

7. **SpawnNewTetromino и Game Over при заполненном верху**

   - Заполнить верхнюю строку `Grid`.
   - Смоделировать ситуацию «фигура упала, нужно заспавнить новую»,
     вызвать `SpawnNewTetromino()` и/или `UpdatePlaying()`:
     - если новая фигура сразу коллидит, `SpawnNewTetromino` возвращает `false`;
     - `_state` переходит в `GameState.GameOver`;
     - `_gameOverDrawn` сбрасывается.

## 3. Интеграционные / функциональные сценарии

### 3.1. Игровой цикл падения и очистки

1. **Стандартный цикл**

   - Инициализировать игру в состоянии `Playing`.
   - Симулировать несколько десятков кадров (`UpdatePlaying`) без ввода:
     - фигура падает, достигает дна, мёрджится;
     - при заполнении строки вызывается `ClearLines`, счёт/линии обновляются;
     - создаётся новый `Tetromino`.

2. **Game Over в процессе игры**

   - Заполнить верхнюю часть сетки так, чтобы следующая фигура не могла появиться.
   - Продолжить вызовы `UpdatePlaying` до попытки спавна:
     - игра переходит в `GameOver`;
     - дальнейшие `UpdatePlaying` не изменяют поле.

### 3.2. Стейт-машина и ввод

1. **Главное меню**

   - Симулировать нажатия `UpArrow/DownArrow`:
     - `_mainMenuSelectedIndex` циклически ходит по массиву `_mainMenuItems`;
     - при переходе индекс 0 ⇄ последний.
   - `Enter`:
     - на `"Start"` → переход в `Playing`, вызов `UiFrameRenderer.DrawStaticFrame`, флаги `_mainMenuDrawn=false`, `_pausedDrawn=false`.
     - на `"Help"` → `GameState.Help`, `_helpDrawn=false`.
     - на `"Settings"` → `GameState.Settings`, `_settingsDrawn=false`, `_settingsSelectedIndex` равен текущей сложности.
     - на `"Exit"` → игра корректно завершает работу (для авто-теста можно вместо `Environment.Exit` использовать обёртку).

2. **Help**

   - В состоянии `Help` симулировать `Enter`, `Escape`, `Spacebar`:
     - `_state` возвращается в `MainMenu`;
     - `_mainMenuDrawn=false`, `_helpDrawn=false`.

3. **Settings**

   - `UpArrow/DownArrow` в `Settings`:
     - `_settingsSelectedIndex` циклически меняется в пределах `_difficultyOptions`.
   - `Enter`:
     - `_difficulty` принимает соответствующее значение;
     - `_dropInterval` пересчитывается через `GetDropInterval`;
     - переход в `MainMenu`, `_mainMenuDrawn=false`, `_settingsDrawn=false`.
   - `Escape`:
     - возвращение в `MainMenu` без изменения `_difficulty` и `_dropInterval`.

4. **Пауза**

   - В `Playing` по клавише `P`:
     - переход в `Paused`;
     - `_pausedDrawn=false` (overlay должен отрисоваться один раз).
   - В `Paused`:
     - `P` → возврат в `Playing`, `_pausedDrawn=false` для будущих пауз;
     - `Esc` → вызов `ResetGame`, переход в `MainMenu`, сброс `_mainMenuDrawn` и `_pausedDrawn`.

5. **Game Over**

   - При переходе в GameOver:
     - `_state == GameState.GameOver`;
     - `_gameOverDrawn=false`.
   - Любая клавиша в `HandleInputGameOver`:
     - `_state == GameState.MainMenu`;
     - `_mainMenuDrawn=false`, `_gameOverDrawn=false`.

6. **Дребезг ввода**

   - Набор быстрых вызовов `HandleInput*` с имитацией часто повторяющихся клавиш (стрелки, Enter, Esc, P):
     - не должно быть исключений;
     - стейт-машина не застревает в промежуточном состоянии;
     - флаги `_mainMenuDrawn`, `_helpDrawn`, `_settingsDrawn`, `_pausedDrawn` ведут себя консистентно (экраны перерисовываются только при смене состояния или выделения).

## 4. Тесты рендеринга и консольного ввода

Для автоматизации рекомендуется ввести обёртку над `Console` (например, `IConsole`), чтобы тесты могли перехватывать `SetCursorPosition` и `Write` без реального терминала.

### 4.1. GameRenderer.Render

1. **Пустое поле + фигура**

   - `Grid` пустой, есть `currentTetromino`.
   - После `Render`:
     - в вычисленном буфере на месте фигуры стоят `'█'`;
     - остальные клетки — `'.'`;
     - координаты соответствуют `X`, `Y`, и размеру `Shape`.

2. **Фигура + зафиксированные блоки**

   - В сетке есть занятые клетки + активная фигура.
   - Проверить, что рендерит объединённую картинку:
     - ни один блок фигуры не «стирает» фиксированный блок;
     - нет выхода за границы.

### 4.2. UiFrameRenderer.DrawBox / DrawStaticFrame

1. **Рамка**

   - Проверить, что:
     - в углах используются корректные символы;
     - горизонтальные/вертикальные линии выводятся правильной длины;
     - цвет после вызова возвращается к исходному (`Console.ForegroundColor` сохраняется).

2. **StaticFrame**

   - После `DrawStaticFrame`:
     - рамка поля соответствует размерам `board.Width` и `board.Height`;
     - панели `STATS` и `INFO` вписываются в окно;
     - текст `Score/Level/Lines` и подсказки управления не пересекают рамки.

### 4.3. UiStatsRenderer.RenderStats

- Выводит значения `score`, `level`, `lines`:
  - с форматированием по ширине 6 символов;
  - по фиксированным координатам `StatsValueX`/`ScoreLabelY` и т.д.;
  - не изменяет цвет консоли глобально (восстановление предыдущего цвета).

### 4.4. RenderMainMenu / RenderHelp / RenderSettings

1. **Размеры окон**

   - `MainMenu`: бокс 50×12, все строки меню и подсказка целиком внутри рамки.
   - `Help`: бокс 50×10, все строки помощи вписываются по ширине и высоте.
   - `Settings`: бокс 50×10, строки сложности и подсказки не пересекают границы.

2. **Флаги отрисовки**

   - При повторном вызове `Render*` без смены состояния и индексов `_mainMenuDrawn/_helpDrawn/_settingsDrawn` предотвращают лишнюю перерисовку (функция выходим сразу).

### 4.5. Пауза (RenderPaused)

1. **Окно паузы внутри поля**

   - Оверлей `PAUSED`:
     - полностью находится внутри рамки `FIELD` (между левым/правым бордерами);
     - все строки текста короче внутренней ширины рамки;
     - при выходе из паузы и следующем `RenderPlaying` не остаётся артефактов вне поля.

2. **Заливка фона**

   - Внутри рамки паузы фон заполняется пробелами до полного перекрытия сетки, чтобы точки/элементы поля не просвечивали.

## 5. Кроссплатформенные и окруженческие проверки

Эти сценарии в первую очередь предполагаются как **ручные** (или полуавтоматические) прогоны.

1. **Размер консоли**

   - Рекомендуемый размер: не меньше 80×30.
   - Проверка при 80×30:
     - игровое поле, STATS и INFO полностью отображаются;
     - окна MainMenu/Help/Settings не обрезаются.
   - Пограничный случай: уменьшенное окно → убедиться, что как минимум нет `ArgumentOutOfRangeException` при `SetCursorPosition` (поведение задокументировать).

2. **ОС и терминалы**

   - Windows: PowerShell / Windows Terminal.
   - Linux: стандартный терминал (bash).
   - macOS: Terminal/iTerm.
   - Проверить:
     - корректное отображение символов рамки (Unicode псевдографика);
     - цветовую схему (`ConsoleColor`);
     - работу клавиш: стрелки, Enter, Escape, P.

3. **Кодировки и локали**

   - Запуск в UTF-8, CP866, Windows-1251 (где актуально).
   - Проверка:
     - русский текст в подсказках читаем;
     - рамки не превращаются в «?».
   - При необходимости в README указать требуемую кодировку.

4. **Сборки и публикация**

   - `dotnet publish -c Release` для:
     - `win-x64`;
     - `linux-x64` (self-contained при необходимости).
   - Smoke-запуск собранных бинарников на «чистой» машине без SDK:
     - игра стартует;
     - основные сценарии (start → игра → game over → меню → exit) отрабатывают.

5. **Производительность и длительная работа**

   - Запуск на сложности `Hard` с активной игрой или симуляцией падения:
     - несколько тысяч кадров / 10–30 минут.
   - Наблюдения:
     - нет заметного роста потребления памяти;
     - нет усиливающегося мерцания;
     - игра остаётся отзывчивой (управление не деградирует).

## 6. Дымовой чек-лист перед релизом

Этот список можно прогонять вручную перед каждой сборкой релиза.

1. **Запуск приложения**

   - `dotnet run` или запуск бинарника:
     - отображается главное меню;
     - стрелки переключают пункты, Enter работает.

2. **Новая игра (Normal)**

   - Запуск игры:
     - фигуры падают;
     - можно двигать/вращать фигуры стрелками;
     - при заполнении линии она исчезает, счёт и количество линий растут.

3. **Пауза**

   - В процессе игры нажать `P`:
     - поверх поля появляется окно паузы;
     - текст внутри окна не вылезает за рамку;
     - `P` возвращает в игру без артефактов на поле;
     - `Esc` из паузы возвращает в главное меню.

4. **Смена сложности**

   - В Settings:
     - переключиться на `Easy` / `Hard`;
     - вернуться в меню и стартовать игру;
     - убедиться, что скорость падения заметно отличается (Easy медленнее Hard).

5. **Game Over и рестарт**

   - Заполнить поле до фатальной высоты:
     - появляется экран Game Over;
     - любая клавиша возвращает в меню;
     - после нового старта поле пустое, статистика обнулена.

6. **Help / Settings**

   - Зайти в Help:
     - текст подсказок и рамка не пересекаются;
     - `Enter` и `Esc` возвращают в меню.
   - Зайти в Settings:
     - подсветка текущей сложности;
     - стрелки перемещают выбор, Enter сохраняет, Esc отменяет.

7. **Выход**

   - В меню выбрать Exit:
     - экран очищается;
     - цвета и видимость курсора возвращаются в дефолтное состояние;
     - приложение завершается без ошибок.

# Задачи по сборке и запуску тестов из TestPlan

Ниже — чек-лист, который помогает пошагово собрать и запускать тесты из `TestPlan.md` **только через терминал**. Список разбит по уровням тестирования и опирается на стандартные команды .NET CLI.

## 1. Базовая инфраструктура тестов

1. Создать проект с тестами (xUnit, чтобы не добавлять новых зависимостей):
   - `dotnet new xunit -n MaxFunkTetris2024.Tests`
   - `dotnet sln add MaxFunkTetris2024.Tests/MaxFunkTetris2024.Tests.csproj`
   - `dotnet add MaxFunkTetris2024.Tests/MaxFunkTetris2024.Tests.csproj reference MaxFunkTetris2024.csproj`
2. Оформить общие фикстуры/билдеры для фигур и доски (минимум: фабрика Tetromino с формами O/I/T/J/L/S/Z; хелпер для заполнения строк поля).
3. Договориться о нейминге тестов: `ClassName_MethodName_State_Expected`.
4. Базовые команды запуска:
   - `dotnet test` — все тесты.
   - `dotnet test --filter Category=Unit` — только юнит-тесты ядра.
   - `dotnet test --filter Category=Integration` — интеграционные.
   - `dotnet test --filter Category=Rendering` — рендеринг (если понадобится изолировать).

## 2. Юнит-тесты ядра (см. раздел 2 TestPlan)

1. **Tetromino**
   - Повороты всех 7 фигур, 4-кратный цикл возвращает форму.
   - Стартовая позиция: `Y == 0`, корректный `X`, нет выхода за правый край.
   - `SaveState/RestoreState` без утечек ссылок.
   - `Game.RotateTetromino` откатывает состояние при коллизии.
2. **GameBoard**
   - `IsCollision` на границах и при перекрытии с занятыми клетками.
   - `MergeTetromino` пишет только в допустимые координаты, игнорирует `y < 0`.
   - `ClearLines/ShiftLinesDown`: один ряд, несколько подряд, через один.
3. **Game (логика без консоли)**
   - Таймер/скорость падения для Easy/Normal/Hard.
   - Увеличение счета и уровня по очищенным линиям.
   - Переходы стейт-машины: Start → Playing → Pause → GameOver → Menu.
4. **Скоростные проверки**
   - Симулировать несколько сотен тиков падения без мерцаний счетчиков/состояний.

## 3. Интеграционные тесты

1. Генерация новой фигуры, её падение и merge на дно без коллизий.
2. Полное заполнение строки и пересчет score/lines/level.
3. Game over при коллизии новой фигуры с верхом поля.
4. Переходы экранов (menu → game → pause → resume → game over → menu) без сброса статистики вне нужных мест.

## 4. Тесты рендеринга (консольный вывод)

1. Проверка рамок `GameRenderer`: размеры поля/статистики/инфо (можно замерять через подмену `IConsole`).
2. Отрисовка фигур в поле: координаты и цвета соответствуют Grid.
3. Меню/Help/Settings: строки не выходят за рамки, подсветка активного пункта есть.
4. Пауза: окно «PAUSED» внутри поля, фон зачищает содержимое сетки.

## 5. Окруженческие/кроссплатформенные проверки

1. Сборка `dotnet publish -c Release -r win-x64` и `-r linux-x64` (self-contained по необходимости).
2. Ручной smoke-запуск собранных бинарников: `./MaxFunkTetris2024` с проверкой сценария start → game → game over → menu → exit.
3. Параметры терминала: запуск при 80×30, проверка рамок и отсутствия `ArgumentOutOfRangeException`.
4. Кодировки: прогон в UTF-8/CP866/Windows-1251, визуальная проверка рамок и подсказок.

## 6. Дымовой чек-лист (быстрые проверки перед релизом)

1. `dotnet run` → главное меню, навигация стрелками/Enter.
2. Новая игра (Normal): падение и вращение фигур, очистка линии увеличивает счет/lines.
3. Пауза `P`: окно внутри поля, возврат без артефактов, `Esc` из паузы ведет в меню.
4. Settings: смена сложности влияет на скорость падения.
5. Game Over: заполнить поле, экран появляется, новая игра стартует с пустым полем и обнуленной статистикой.
6. Exit: выход очищает экран, возвращает цвета/курсор.

## 7. Полезные нюансы

- Для рендеринг-тестов удобно внедрить интерфейс консоли (`IConsole`) и подменять его тестовым буфером.
- Категории (`[Trait("Category", "Unit")]`) помогут фильтровать наборы через `--filter`.
- Если тесты зависят от времени, инжектируйте таймер или используйте монотонный счетчик тиков, чтобы убрать флаки.
